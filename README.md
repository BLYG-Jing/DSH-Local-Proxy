# DSH Local Proxy

## 1. 这是做什么的？

**（1）解决痛点：** DeepSeek Harness Web 默认主要适合在本机访问。当用户尝试从局域网或其他受信任网络访问时，可能会因为访问来源检查和浏览器安全策略，遇到连接受限、功能异常等问题，难以获得与本机访问一致的体验。

**（2）项目定义：** DSH Local Proxy 是 DeepSeek Harness Web 的本地网络代理。它提供一个带密码验证的代理入口，转发 HTTP 和 WebSocket 请求，并处理部分本机访问兼容问题，让远程访问更加方便。

**（3）简单地说：** 启动本项目后，访问代理生成的新链接，即可通过一个受密码保护的入口访问 DSH Web，绕过由远程访问来源引起的限制。

## 2. 启动方式

### 运行要求

- Linux
- Node.js 18 或更高版本
- DeepSeek Harness Web 已在本机运行

### 一键启动

克隆仓库或执行 `git pull` 后，在项目目录运行：

```bash
./start.sh
```

启动时，脚本会依次要求输入：

| 填写内容 | 解释 |
| --- | --- |
| 代理监听端口 | 新的 DSH Web 访问入口所使用的端口 |
| Harness Web 上游端口 | 已经运行的 DeepSeek Harness Web 所使用的端口 |
| 登录密码 | 访问新代理入口时需要输入的密码 |

配置会保存到本地 `.env` 文件。代理地址为：

```text
http://127.0.0.1:你输入的代理监听端口/
```

如果脚本没有执行权限，可以先运行：

```bash
chmod +x start.sh
./start.sh
```

- 本项目是社区工具，不是 DeepSeek 官方产品，也不保证 Harness Web 的稳定性、兼容性或持续可用性。
- 使用本项目造成的配置错误、服务中断、数据丢失或其他直接、间接损失，由使用者自行承担。
- 请使用足够长且唯一的密码，并妥善保存自己输入的密码。
- 默认只监听本机地址 `127.0.0.1`，这是较安全的默认设置。
- 不建议直接监听 `0.0.0.0` 或将服务暴露到公网。若必须远程访问，请自行配置防火墙、HTTPS 和访问控制。
- 如果使用未加密的 HTTP 连接，密码和会话信息可能被窃听。面向不可信网络访问时，请先配置 HTTPS。
- 不要把 `.env`、真实密码、Cookie、私钥或其他敏感信息提交到 Git 仓库。
- 使用前请确认你有权访问和转发目标 Harness Web 服务，并自行遵守相关法律、协议和组织规定。
